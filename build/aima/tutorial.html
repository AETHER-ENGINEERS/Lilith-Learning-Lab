Chapter 1

Introduction to AI

What is AI?

Artificial Intelligence (AI) is the study and construction of agents that perceive an environment and act in it to achieve goals. The field has four classic ways of defining its aim: acting humanly (pass the Turing test), thinking humanly (model the mind), thinking rationally (follow the laws of logic) and acting rationally (do the best thing given what is known).

Modern AI mostly follows the last view. A rational agent chooses the action that is expected to maximise its performance measure, given what it has perceived. This definition is general: it covers a thermostat, a chess program and a self-driving car.

The Standard Model and the Value Alignment Problem

In the standard model we build machines that optimise an objective that we specify. This works when the objective is complete, but a machine given a slightly wrong objective may pursue it with perfect efficiency and cause harm. This is the value alignment problem: making sure the machine's objectives match human preferences. A newer view builds machines that are uncertain about the true objective and therefore defer to people.

A Short History

  • 1943-1955: artificial neurons (McCulloch and Pitts), Turing's paper on machine intelligence, early neural networks.
  • 1956: the Dartmouth workshop names the field "artificial intelligence".
  • 1956-1969: early enthusiasm: logic provers, game players, the perceptron.
  • 1966-1973: a dose of reality: combinatorial explosion, limits of single-layer perceptrons.
  • 1969-1986: expert systems capture human knowledge as rules.
  • 1986 onward: back-propagation revives neural networks; probability and statistics enter the mainstream.
  • 2011 onward: big data, fast hardware and deep learning give breakthroughs in vision, speech, games and language.

State of the Art

AI systems now play Go and chess above human level, recognise images and speech, translate languages, drive vehicles in limited conditions, help diagnose disease and write text and code. Each of these successes is narrow; general intelligence remains an open goal.

Risks and Benefits

Benefits include automation of dull work, scientific discovery and better health care. Risks include bias in decisions, loss of privacy, surveillance, misuse in weapons, job disruption and loss of control. Responsible AI means measuring and managing these risks from the start.

Chapter 2

Intelligent Agents

Agents and Environments

An agent maps what it perceives to an action. The sequence of everything it has perceived is the percept sequence. The agent function gives the action for each percept sequence; the agent program is the code that implements it.

Good Behaviour: Rationality

A performance measure scores a sequence of environment states. A rational agent picks, for each percept sequence, the action expected to maximise that score using the knowledge it has. Rationality is not omniscience: it depends on what the agent knows and can perceive. It also includes exploration and learning: gathering information is part of acting well.

The Task Environment (PEAS)

Describing a problem starts with PEAS: Performance measure, Environment, Actuators, Sensors. For an automated taxi: performance is safety, speed and comfort; the environment is roads and traffic; actuators are steering, brakes and horn; sensors are cameras, GPS and speedometer.

Properties of Environments

Property Easy Hard

Chess is fully observable, deterministic, discrete and multi-agent. Taxi driving is partially observable, stochastic, sequential, dynamic and continuous: the hardest case.

Structure of Agents

  • Simple reflex agents act on the current percept using condition-action rules.
  • Model-based reflex agents keep an internal state that tracks the parts of the world they cannot see, using a transition model and a sensor model.
  • Goal-based agents consider the future consequences of actions in order to reach a goal.
  • Utility-based agents score outcomes with a utility function so they can trade off conflicting goals and handle uncertainty.
  • Learning agents add a learning element that improves the performance element, a critic that gives feedback, and a problem generator that proposes exploratory actions.

How Agent Components Represent the World

Representations range from atomic (a state is a black box), through factored (a state is a set of variables with values), to structured (objects and relations between them). More expressive representations are more powerful but make reasoning and learning harder.

Term Meaning

PEAS Performance measure, Environment, Actuators, Sensors: the task description.
Utility-based agent An agent that compares outcomes with a utility score and handles trade-offs.
Learning agent An agent with a learning element that improves its performance element.

Check your understanding

Q1. Is a table-driven agent practical?

Answer: No. The table grows with every possible percept sequence, so it is far too big.

Q2. Give one fully observable and one partially observable environment.

Answer: Chess is fully observable; driving a taxi is partially observable.

Q3. What does a goal-based agent add to a model-based reflex agent?

Answer: A goal, so it can consider the future consequences of its actions.

Chapter 3

Solving Problems by Searching

Problem-Solving Agents

A problem-solving agent with a goal finds a sequence of actions that reaches it. The process is: formulate the goal, formulate the problem, search for a solution, then execute it. This works best in observable, deterministic, discrete, known environments.

Formal Definition of a Search Problem

A search problem consists of:

  • a set of states (the state space);
  • an initial state;
  • one or more goal states (or a goal test);
  • the actions available in each state;
  • a transition model giving the result of an action;
  • an action cost function.

A solution is a path from the initial state to a goal; an optimal solution has the lowest path cost. Example: route finding on a map, where states are cities, actions are drives and cost is distance.

Search Algorithms

Search builds a search tree from the initial state. A node holds a state, its parent, the action that led to it and the path cost. The frontier is the set of nodes that have been generated but not expanded. The generic loop: take a node from the frontier, test it, expand it and add the children. A reached table avoids revisiting states (graph search).

Measuring performance

  • Completeness: does it find a solution if one exists?
  • Cost optimality: is the solution the cheapest?
  • Time complexity and space complexity, in terms of branching factor b, solution depth d and maximum depth m.

Uninformed (Blind) Search

Algorithm Frontier Complete Optimal Time Space
Breadth-first FIFO queue Yes Yes (equal costs) O(b^d) O(b^d)
Uniform-cost Priority by path cost Yes Yes O(b^(1+C*/e)) same
Depth-first LIFO stack No (infinite paths) No O(b^m) O(bm)
Depth-limited Stack with a depth limit l No No O(b^l) O(bl)
Iterative deepening Repeated depth-limited Yes Yes (equal costs) O(b^d) O(bd)
Bidirectional Two frontiers Yes Yes (equal costs) O(b^(d/2)) O(b^(d/2))

Breadth-first expands the shallowest node first, so it finds the shortest path in steps but uses much memory. Uniform-cost expands the node with the lowest path cost. Depth-first uses little memory but can get lost. Iterative deepening combines the memory of depth-first with the completeness of breadth-first and is the preferred blind method for large spaces.

Informed (Heuristic) Search

A heuristic h(n) estimates the cost from node n to a goal. It lets the search prefer promising nodes.

  • Greedy best-first search expands the node with the smallest h(n). It is fast but neither optimal nor complete in general.
  • A* search expands the node with the smallest f(n) = g(n) + h(n), where g(n) is the cost so far. If h is admissible (never overestimates) and, for graph search, consistent (h(n) <= c(n, a, n') + h(n')), A* is complete and optimal.
  • Weighted A* uses f = g + W h with W > 1: faster, but only bounded-suboptimal.
  • Memory-bounded variants: IDA*, recursive best-first search (RBFS) and simplified memory-bounded A* (SMA*).

Designing heuristics

Good heuristics come from relaxed problems: remove constraints, solve the easier problem exactly, and use its cost. For the 8-puzzle, ignoring that tiles block each other gives the Manhattan distance. Another source is pattern databases, which store exact costs of solving sub-problems, and learning heuristics from experience. A heuristic that dominates another (always at least as large, still admissible) expands fewer nodes.

Term Meaning

Completeness A search finds a solution whenever one exists.
Admissible heuristic A heuristic that never overestimates the true remaining cost.

Check your understanding

Q1. Why is breadth-first search often too costly?

Answer: It stores every node at the current depth, so memory grows like b to the power d.

Q2. What does iterative deepening combine?

Answer: The small memory of depth-first search with the completeness and optimality of breadth-first search.

Q3. How can you build a heuristic?

Answer: Solve a relaxed version of the problem, or use a pattern database of sub-problem costs.

Chapter 4

Search in Complex Environments

Local Search and Optimisation

When the path does not matter and only the final state does (scheduling, circuit layout, n-queens), local search keeps a single current state and moves to neighbours. It uses little memory and works in huge spaces. The landscape has a global maximum, local maxima, ridges and plateaus.

  • Hill climbing moves to the best neighbour and can stall at local maxima. Variants: stochastic, first-choice, random-restart.
  • Simulated annealing sometimes accepts a worse move with probability e^(dE/T), where the temperature T falls slowly. Early randomness escapes local maxima; later it settles.
  • Local beam search keeps k states, choosing the best k successors of all of them.
  • Evolutionary algorithms keep a population, select fit individuals, recombine them (crossover) and mutate them.

Search in Continuous Spaces

For continuous variables, use gradient ascent or descent: x <- x + alpha grad f(x). Newton-Raphson uses second derivatives for faster convergence. Constrained optimisation adds restrictions; linear programming has linear objective and constraints and can be solved efficiently, and convex optimisation generalises this.

Search with Nondeterministic Actions

When actions have uncertain outcomes, a solution is a contingency plan, not a path. It uses conditional branches (if-then-else). An AND-OR search tree has OR nodes (the agent chooses an action) and AND nodes (all possible outcomes must be handled).

Search in Partially Observable Environments

With no or limited sensing the agent works with a belief state: the set of states it might be in. In a sensorless (conformant) problem, a plan must work from any state in the belief set. In general, after each action and percept the belief state is updated (predict, then update with the percept).

Online Search and Unknown Environments

In online search the agent must act and explore at once, because it does not know the map or the effects of actions. It must also be able to undo moves (safe exploration). Online DFS and LRTA* (learning real-time A*) improve their cost estimates as they travel.

Key terms

Term Meaning
Local search Search that keeps only the current state and moves to neighbours.
Hill climbing Move to the best neighbour; stop at a peak.
Simulated annealing Hill climbing that sometimes accepts worse moves, less often over time.
Genetic algorithm Search that evolves a population by selection, crossover and mutation.
Belief state The set of states the agent thinks it might be in.

Check your understanding

Q1. Why can hill climbing get stuck?

Answer: On a local maximum, a ridge or a plateau, where no neighbour is better.

Q2. What does random restart do?

Answer: It runs hill climbing from many starting points and keeps the best result.

Q3. When do we need belief states?

Answer: When the environment is partially observable or actions have uncertain outcomes.

Chapter 5

Adversarial Search and Games

Game Theory Basics

AI studies deterministic, turn-taking, two-player, zero-sum, perfect-information games such as chess and Go. A game has an initial state, a to-move function, actions, a result function, a terminal test and a utility at terminal states. The agent is MAX, the opponent MIN.

Minimax Search

The minimax value of a node is the utility for MAX of playing optimally from there, assuming MIN also plays optimally. MAX chooses the maximum of the children's values; MIN the minimum. Minimax is a depth-first search of the game tree. Its time is O(b^m); the space is O(bm).

Alpha-Beta Pruning

Alpha-beta pruning gives the same answer as minimax but skips branches that cannot affect the result. alpha is the best value found so far for MAX along the path; beta is the best for MIN. If a node's value is already worse for the player than an option available earlier, the rest of its children are skipped. With perfect move ordering, the time falls to O(b^(m/2)), allowing about twice the search depth. Good ordering uses killer moves, the best move from a shallower search, and transposition tables that cache positions already evaluated.

Heuristic Evaluation and Cutoffs

Real games are too large to search to the end. Instead, cut off the search at a depth limit and apply a heuristic evaluation function that estimates the utility of a non-terminal position, typically a weighted sum of features such as material and mobility. Techniques include iterative deepening, quiescence search (continue in unstable positions) and forward pruning.

Monte Carlo Tree Search

MCTS builds a search tree selectively using random playouts. Four steps repeat: selection (descend by a policy such as UCB1, which balances exploitation and exploration), expansion, simulation (a playout to the end) and backpropagation of the result. It works without a hand-written evaluation function and powers modern Go programs, where it was combined with neural networks in AlphaGo.

Stochastic Games

With chance (dice, cards) add chance nodes: a node's value is the expected value over outcomes. This is expectiminimax. Because the evaluation function must now measure expected utility, it should be a positive linear transformation of the true probability of winning.

Limitations

Game search assumes a known model and exact rules. Its limits include huge branching factors (Go), partial observability (poker) and the need for a good evaluation. Modern systems learn both policy and evaluation by self-play.

Key terms

Term Meaning
Minimax Choose the move that is best assuming the opponent plays best.
Alpha-beta pruning Skip branches that cannot change the minimax decision.
Evaluation function An estimate of how good a position is when the search is cut off.
Monte Carlo tree search Choose moves by many random playouts guided by statistics.
Zero-sum game One player's gain is exactly the other's loss.

Check your understanding

Q1. How much can alpha-beta save with perfect move ordering?

Answer: It can roughly double the depth reached in the same time.

Q2. Why use Monte Carlo tree search for Go?

Answer: Go has a huge branching factor and positions are hard to evaluate by hand.

Q3. What is the horizon effect?

Answer: A bad event just past the search depth is not seen, so the agent may delay it uselessly.

Chapter 6

Constraint Satisfaction Problems

Defining a CSP

A constraint satisfaction problem has variables X1..Xn, each with a domain of values, and constraints that limit the combinations. A solution assigns every variable a value that satisfies all constraints. Examples: map colouring (adjacent regions differ), Sudoku, scheduling, circuit layout.

Constraints can be unary, binary, or higher-order (global constraints such as Alldiff). A binary CSP is drawn as a constraint graph.

Constraint Propagation

Inference reduces domains by enforcing local consistency:

  • Node consistency: every value satisfies the unary constraints.
  • Arc consistency: for every arc (Xi, Xj), each value of Xi has some compatible value in Xj. The AC-3 algorithm repeatedly revises arcs and re-queues affected neighbours, in O(c d^3) time.
  • Path consistency and k-consistency check larger groups of variables.
  • Global constraints use special algorithms, for example Alldiff detects when m variables share fewer than m values.

Backtracking Search

Backtracking assigns one variable at a time and backs up when a conflict appears. It is smarter with heuristics:

  • Minimum remaining values (MRV): pick the variable with the fewest legal values.
  • Degree heuristic: break ties by the most constraints on unassigned variables.
  • Least constraining value: try the value that rules out the fewest options for neighbours.
  • Forward checking and MAC (maintaining arc consistency) propagate after every assignment.
  • Conflict-directed backjumping returns to the variable that actually caused the failure.

Local Search for CSPs

Min-conflicts starts with a full assignment and repeatedly changes a variable in conflict to the value that causes the fewest conflicts. It solves n-queens for a million queens in a few steps, and is widely used for scheduling.

Problem Structure

If the constraint graph is a tree, the CSP can be solved in O(n d^2) by making it arc-consistent from the leaves to the root. General graphs can be reduced by cutset conditioning (fix a set of variables so the rest forms a tree) or by tree decomposition. Symmetries can be broken with extra constraints to cut the search.

Key terms

Term Meaning
CSP A problem defined by variables, domains and constraints.
Arc consistency Every value of a variable has a supporting value in each neighbour.
Backtracking search Assign variables one at a time and undo when a constraint fails.
MRV heuristic Pick the variable with the fewest legal values left.
Min-conflicts Local search that repairs the variable in the most conflicts.

Check your understanding

Q1. Why are CSPs easier than general search?

Answer: The structure lets us prune whole families of assignments by constraint propagation.

Q2. What does forward checking do?

Answer: After an assignment it removes inconsistent values from neighbouring variables' domains.

Q3. When is a CSP solvable in linear time?

Answer: When its constraint graph is a tree.

Chapter 7

Logical Agents

Knowledge-Based Agents

A knowledge-based agent keeps a knowledge base (KB): a set of sentences written in a formal language. It works in a loop. It TELLs the KB what it perceives, ASKs the KB what to do, and then TELLs the KB which action it took. The big idea is the split between what the agent knows (the sentences) and how it reasons (the inference procedure). You can improve either one without touching the other.

Two styles of building the KB exist. The declarative approach writes down facts and lets inference do the rest. The procedural approach hard-codes behaviour. Real agents usually mix both.

The Wumpus World

The wumpus world is a small grid cave used as a running example. It contains a monster (the wumpus), bottomless pits and a heap of gold. The agent perceives a stench next to the wumpus, a breeze next to a pit, a glitter on the gold square, a bump when it hits a wall, and a scream when the wumpus dies.

Feature Value
Environment Partially observable, discrete, static, sequential
Goal Grab the gold and climb out alive
Danger Falling into a pit, meeting a live wumpus
Actions Move forward, turn, grab, shoot (one arrow), climb

The agent cannot see which squares are safe. It must infer safety from breezes and stenches. For example, if square [1,2] has no breeze, then neighbouring squares cannot hold a pit.

Logic: Syntax, Semantics, Models

  • Syntax says which strings are well-formed sentences.
  • Semantics says what a sentence means: in each possible world (a model) it is true or false.
  • A sentence entails another (written α ⊨ β) when β is true in every model where α is true.
  • A procedure is sound if it derives only entailed sentences, and complete if it can derive every entailed sentence.

Model checking enumerates models to test entailment. It is easy to understand but costs time exponential in the number of symbols.

Propositional Logic

Propositional logic uses symbols that are true or false, joined by the connectives not (¬), and (∧), or (∨), implies (⇒) and if and only if (⇔).

Useful facts:

  • A sentence is valid if true in all models (a tautology) and satisfiable if true in at least one.
  • Inference rules such as modus ponens (from α and α ⇒ β, conclude β) and resolution are sound.
  • Conjunctive normal form (CNF) is an AND of ORs of literals; any sentence can be converted to it.

Wumpus rules in propositional form

Let B(x,y) mean "breeze at x,y" and P(x,y) mean "pit at x,y". The rule "a square is breezy exactly when a neighbour has a pit" is written once per square:

B(1,1) ⇔ (P(1,2) ∨ P(2,1))

The weakness is clear: one rule per square, so the KB grows with the cave.

Inference by Theorem Proving

Resolution

Resolution takes two clauses that contain complementary literals and produces a new clause without them. To prove KB ⊨ α, add ¬α to the KB, convert to CNF and resolve repeatedly. If the empty clause appears, the set is contradictory and α follows. Resolution is sound and complete for propositional logic.

Horn clauses and chaining

A Horn clause has at most one positive literal. KBs made only of Horn clauses allow very fast inference:

  • Forward chaining starts from known facts and fires rules whose premises are all true, until the query appears. It is data-driven.
  • Backward chaining starts from the query and looks for rules that conclude it, then tries to prove their premises. It is goal-driven.

Both run in time linear in the size of the KB.

Efficient Model Checking: SAT Solvers

The SAT problem asks whether a propositional formula is satisfiable. It is NP-complete, yet modern solvers handle formulas with millions of variables.

  • DPLL is a backtracking search with three tricks: early termination, pure symbol heuristic and unit clause heuristic.
  • CDCL (conflict-driven clause learning) adds learned clauses so the same mistake is never repeated.
  • Local search such as WalkSAT flips variables to reduce unsatisfied clauses; it is incomplete but often fast.

Many planning and verification problems are turned into SAT and handed to a solver.

Agents Based on Propositional Logic

A logical agent can keep a current-state belief: which squares are known safe, which may hold pits. It uses fluents (facts that change over time) with a time index, and effect axioms plus frame axioms (what does not change). The frame problem is the cost of writing all the "unchanged" facts. Successor-state axioms say, for each fluent, how it becomes true at the next step.

Summary

  • A knowledge-based agent TELLs and ASKs a KB.
  • Logic gives syntax, semantics and entailment; inference should be sound and ideally complete.
  • Resolution is complete for propositional logic; Horn-clause chaining is linear.
  • SAT solvers (DPLL, CDCL, WalkSAT) make propositional reasoning practical.
  • Propositional logic is limited because it cannot talk about objects and relations compactly.

Key terms

Term Meaning
Knowledge base A set of sentences the agent holds to be true.
Entailment α entails β when β is true in every model where α is true.
Resolution An inference rule that is complete for propositional logic.
Horn clause A clause with at most one positive literal.
SAT solver A program that decides whether a propositional formula is satisfiable.

Check your understanding

Q1. What is the difference between sound and complete inference?

Answer: Sound derives only what is entailed; complete can derive everything that is entailed.

Q2. Why are Horn clauses attractive?

Answer: Forward and backward chaining decide them in time linear in the size of the KB.

Q3. What is the frame problem?

Answer: Stating compactly what does not change when an action is performed.

First-Order Logic

Why Go Beyond Propositional Logic

Propositional logic has no way to say "all squares next to a pit are breezy" in one sentence. First-order logic (FOL) adds objects, relations and functions, and the quantifiers for all (∀) and there exists (∃). It is expressive enough for most of mathematics and much of common sense.

Syntax and Semantics

Element Meaning Example
Constant names one object Richard, John
Predicate a relation among objects Brother(Richard, John)
Function maps objects to an object LeftLeg(John)
Variable stands for any object x
Quantifier ∀x or ∃x ∀x King(x) ⇒ Person(x)
Equality two terms are the same object Father(John) = Henry

A model in FOL contains a set of objects (the domain) and an interpretation that says which object each constant names, and which tuples satisfy each predicate.

Quantifier rules of thumb

  • Use ⇒ with ∀: "all kings are persons" is ∀x King(x) ⇒ Person(x).
  • Use ∧ with ∃: "some king is crazy" is ∃x King(x) ∧ Crazy(x).
  • ¬∀x P is the same as ∃x ¬P, and ¬∃x P is the same as ∀x ¬P.

Getting these pairings wrong is the most common beginner mistake.

Using First-Order Logic

Assertions and queries

TELL the KB facts such as King(John); ASK queries such as ∃x Person(x). The answer may be a substitution (binding list) such as {x/John}.

Domains

  • Kinship: Parent, Mother, Grandparent are defined from a few base predicates.
  • Numbers and sets: Peano axioms define the natural numbers; set axioms define membership, union and subset.
  • Lists: Nil and Cons build sequences.

The wumpus world in FOL

Perception rules link percepts to the world: "if the agent perceives a breeze at time t then the agent's square is breezy." One general rule replaces dozens of propositional ones:

∀s Breezy(s) ⇔ ∃r Adjacent(r, s) ∧ Pit(r)

Knowledge Engineering in FOL

A reliable process for building a KB:

  1. Identify the task (which questions must the KB answer?).
  2. Assemble the knowledge from experts and documents.
  3. Decide on a vocabulary of predicates, functions and constants (the ontology).
  4. Encode general knowledge as axioms.
  5. Encode a specific problem instance.
  6. Pose queries and get answers.
  7. Debug the KB: missing axioms give "cannot prove", wrong axioms give wrong proofs.

Summary

  • FOL adds objects, relations, functions and quantifiers to propositional logic.
  • Pair ∀ with ⇒ and ∃ with ∧.
  • A good ontology and a careful knowledge-engineering process matter as much as the logic.

Key terms

Term Meaning
Predicate A relation among objects, such as Brother(x, y).
Quantifier ∀ (for all) or ∃ (there exists).
Domain The set of objects a model contains.
Ontology The vocabulary and structure of concepts chosen for a domain.
Term An expression that names an object: a constant, variable or function application.

Check your understanding

Q1. Which connective goes with ∀ and which with ∃?

Answer: Use ⇒ with ∀ and ∧ with ∃.

Q2. What is ¬∀x P(x) equivalent to?

Answer: ∃x ¬P(x).

Q3. Name two steps of knowledge engineering.

Answer: Decide the vocabulary, and encode the general axioms, then test with queries.

Chapter 9

Inference in First-Order Logic

Reducing to Propositional Inference

Universal instantiation replaces a universally quantified variable by a ground term. Existential instantiation replaces ∃ with a new constant (a Skolem constant). By instantiating with every possible ground term, a FOL KB can be turned into a propositional one. With functions the set of ground terms is infinite, but Herbrand's theorem says that if a sentence is entailed, a finite subset of instantiations proves it. FOL entailment is semidecidable: algorithms can say yes to every entailed sentence, but may run forever on a non-entailed one.

Unification and Lifting

Instantiating blindly creates many useless facts. Lifted inference works with variables directly. The key tool is unification: find a substitution that makes two expressions identical.

Pair Unifier
Knows(John, x) and Knows(John, Jane) {x/Jane}
Knows(John, x) and Knows(y, Mother(y)) {y/John, x/Mother(John)}
Knows(John, x) and Knows(x, Elizabeth) fails (same variable x)

The most general unifier (MGU) is unique up to renaming. The occur check prevents binding a variable to a term that contains it.

Generalised modus ponens applies a rule whose premises unify with known facts and produces the substituted conclusion.

Forward Chaining

A definite clause has exactly one positive literal. Forward chaining repeatedly fires any rule whose premises unify with known facts and adds the new conclusion, until the query is derived or nothing changes. For Datalog knowledge bases (no function symbols) it terminates and is complete. Efficiency tricks include:

  • Pattern matching of rule premises against facts (the Rete network keeps partial matches).
  • Incremental forward chaining: only rules affected by a new fact are rechecked.
  • Irrelevant facts: magic sets restrict work to facts relevant to the goal.

Forward chaining powers production systems and deductive databases.

Backward Chaining

Backward chaining starts with the goal and finds rules whose conclusion unifies with it, then proves their premises depth-first, passing along the growing substitution. It is the engine of Prolog.

  • It is a depth-first search, so it uses little memory.
  • It can loop forever (left recursion) and repeat work; tabling fixes the repetition.
  • Logic programming (Prolog) uses Horn clauses, the closed world assumption and negation as failure.

Resolution

For FOL, convert sentences to clausal form:

  1. Eliminate implications.
  2. Move negation inward.
  3. Standardise variables apart.
  4. Skolemise to remove existential quantifiers.
  5. Drop universal quantifiers.
  6. Distribute ∨ over ∧.

The resolution rule unifies a literal with the negation of one in another clause. Resolution is refutation-complete: if KB ∧ ¬α is unsatisfiable, resolution will find the empty clause. Practical provers add strategies such as unit preference, set of support, input resolution and subsumption (delete clauses that are less general than another). Equality is handled with paramodulation or a demodulation rewrite.

Theorem provers have proved real results: the Robbins conjecture, and they are used to verify hardware and software.

Summary

  • Lifted inference uses unification to avoid blind instantiation.
  • Forward chaining suits data-driven problems; backward chaining suits goal-driven problems.
  • Resolution is refutation-complete for FOL, though search may not halt.

Knowledge Representation

Ontological Engineering

An ontology organises the concepts of a domain. An upper ontology describes the most general concepts (objects, events, time, substances) that every domain shares.

Categories and Objects

  • Categories group objects. They can be predicates (Basketball(b)) or objects (Basketballs) so we can state properties of the category itself.
  • Inheritance passes properties down a hierarchy: members of a subclass have the properties of its superclass.
  • Physical composition (PartOf) and measurements (Length(x) = Inches(1.5)) extend the vocabulary.
  • Natural kinds (tigers) differ from defined kinds (bachelor) because they have no crisp definition.

Events and Time

Event calculus describes fluents and the events that start (Initiates) or end (Terminates) them, and the times at which they hold. Intervals, ordering and processes (continuous events such as flying) are represented with predicates such as Meet, Before, During and Overlap.

Mental Objects and Modal Logic

To talk about what agents know or believe, we need modal logic: operators like K_A(P) ("A knows P") whose arguments are propositions, not objects. Possible-world semantics gives them meaning. The alternative is to treat sentences as reified objects (strings) in FOL.

Reasoning Systems for Categories

  • Semantic networks draw categories as nodes and relations as links; fast inheritance is their strength.
  • Description logics define concepts from other concepts with operators such as And, All, AtLeast. The core tasks are subsumption (is concept A a subset of B?) and classification. They underlie the Web Ontology Language (OWL) and the semantic web.

Reasoning with Default Information

Common sense uses defaults: "birds fly" is true unless the bird is a penguin. Reasoning that takes back conclusions when new facts arrive is nonmonotonic.

  • Circumscription minimises the abnormal cases.
  • Default logic adds rules like "if P holds and it is consistent that Q, conclude Q."
  • Truth maintenance systems (TMS) record why each belief is held, so beliefs can be retracted when their justification disappears.
  • The closed-world assumption treats anything not provably true as false.

Summary

  • Ontologies organise concepts; categories support inheritance.
  • Event calculus represents change; modal logic represents belief and knowledge.
  • Description logics power knowledge graphs and OWL.
  • Nonmonotonic reasoning handles defaults and exceptions.

Chapter 11

Automated Planning

The Planning Problem

Planning finds a sequence of actions that achieves a goal. Unlike search with a black-box successor function, planning uses a factored representation: states are sets of propositions, and actions are described by their effects.

PDDL

The Planning Domain Definition Language (PDDL) describes:

  • the initial state (a conjunction of ground atoms),
  • actions with preconditions (what must hold) and effects (what becomes true or false),
  • the goal (a conjunction of literals).

Example action (air cargo):

Fly(p, from, to): precondition At(p, from) ∧ Plane(p) ∧ Airport(from) ∧ Airport(to); effect ¬At(p, from) ∧ At(p, to).

The closed-world assumption applies: anything not listed is false. The STRIPS assumption means effects only change what is listed, so the frame problem disappears.

Algorithms for Classical Planning

Approach Idea
Forward state-space search start at the initial state, apply applicable actions
Backward (regression) search start from the goal, work back to the start
SAT planning encode "a plan of length k exists" as a SAT problem
Planning graph (GRAPHPLAN) layered graph of possible facts and actions; extracts plans
Partial-order planning commit only to needed orderings

Heuristics for planning

Good heuristics come from relaxed problems:

  • Ignore preconditions: each action may be done anytime.
  • Ignore delete lists: actions never remove facts (very effective; used in FF and its descendants).
  • State abstraction: merge states to build a pattern database.

Planning graphs

A planning graph alternates state levels and action levels. Mutex links mark pairs of actions or facts that cannot hold together. If a goal fact never appears, or only appears mutex, the goal is unreachable within that many steps. The level at which all goal facts appear gives an admissible heuristic.

Hierarchical Planning

A hierarchical task network (HTN) starts with a high-level action and refines it using methods into lower-level steps until only primitive actions remain. It lets experts write the structure of good plans ("to travel: book, pack, go") and scales to very large problems. Angelic semantics reason about the set of outcomes a high-level action might achieve.

Planning and Acting in Nondeterministic Domains

When the world is not fully predictable, plans become more complex:

  • Sensorless (conformant) planning finds a plan that works without observations.
  • Contingent planning builds a plan with conditional branches ("if the door is locked, then ...").
  • Online planning interleaves planning, acting and replanning.

States become belief states (sets of possible states). Fast progress comes from monitoring the execution and replanning when something unexpected occurs.

Time, Schedules and Resources

Real planning needs durations and resources. A scheduling problem assigns start times to actions under ordering constraints and resource limits. The critical path method finds the longest chain of dependent actions and hence the shortest possible total time. Hierarchical planning and constraint solving are combined for jobs such as factory production and space-mission operations.

Analysis of Planning Approaches

  • Forward search with good heuristics is the dominant approach for classical planning.
  • SAT-based planning wins when plans are short and highly constrained.
  • HTN planning is the practical choice when domain knowledge about plan structure is available.

Summary

  • PDDL describes states, actions, and goals in a factored way.
  • Relaxed-problem heuristics make forward search effective.
  • HTNs, contingent plans and online replanning extend planning to realistic settings.

Key terms

Term Meaning
PDDL A language that describes initial state, actions and goals.
Precondition and effect What must hold to act, and what changes afterward.
Delete-relaxation A heuristic that pretends actions never remove facts.
HTN Hierarchical task network: refine high-level tasks into primitive steps.
Contingent plan A plan with branches that depend on observations.

Answer: The frame problem: only the listed effects change.

Answer: Two facts or actions cannot both hold or occur at the same level.

Quantifying Uncertainty

Acting Under Uncertainty

An agent rarely knows the exact state of the world. Logic gives either "true" or "false", which breaks down when sensors are noisy or knowledge is incomplete. A rational agent weighs how likely each outcome is and how much it matters. Decision theory = probability theory + utility theory.

Basic Probability Notation

  • A sample space is the set of all possible worlds; a probability model assigns each world a number between 0 and 1, and the numbers add up to 1.
  • A proposition is a set of worlds; its probability is the sum of the worlds in it.
  • Unconditional (prior) probability P(a) is the belief before evidence. Conditional probability P(a | b) is the belief after learning b:

P(a | b) = P(a ∧ b) / P(b)

  • Random variables have a domain (Weather could be sunny, rain, cloud, snow) and a probability distribution over it. A joint distribution gives the probability of every combination of values of several variables.

Axioms (Kolmogorov)

  1. 0 ≤ P(ω) ≤ 1 for every world.
  2. The probabilities of all worlds sum to 1.
  3. For any proposition, P(a) is the sum of the probabilities of the worlds in a.

Useful consequences: P(¬a) = 1 − P(a), and inclusion-exclusion: P(a ∨ b) = P(a) + P(b) − P(a ∧ b).

Why should an agent follow these axioms? If its betting odds violate them, a clever opponent can construct bets that guarantee the agent loses (the Dutch book argument).

Inference Using Full Joint Distributions

With a full joint table you can answer any query by adding up matching entries. To get P(cavity | toothache):

  1. Sum all entries where toothache is true to get P(toothache).
  2. Sum the entries where both are true.
  3. Divide.

Normalisation simplifies this: compute the unnormalised values for each answer and scale them so they sum to 1; the constant α replaces the division.

The problem: the table has 2ⁿ entries for n Boolean variables. It is useless in practice for large n, so we need structure.

Independence

Two variables are independent if P(a, b) = P(a)P(b), that is, knowing one tells nothing about the other. Independence cuts a joint table into small independent pieces, but absolute independence is rare. A weaker, more useful idea is conditional independence: Toothache and Catch are independent given Cavity. Conditional independence turns exponential tables into products of small ones.

Bayes' Rule and Its Use

Bayes' rule reverses a conditional:

P(b | a) = P(a | b) P(b) / P(a)

It matters because causal knowledge P(symptom | disease) is often easier to get than diagnostic knowledge P(disease | symptom).

Term Name
P(b) prior
P(a | b) likelihood
P(b | a) posterior
P(a) evidence (normaliser)

Worked example. A disease affects 1 in 10,000 people. A test is 99% sensitive with a 1% false-positive rate. If you test positive, the chance you have the disease is only about 1%, because false positives from the huge healthy population outnumber true positives. Ignoring the prior (base-rate neglect) is a classic error.

Bayes' rule combines evidence naively as: P(cause | e₁, e₂) ∝ P(cause) P(e₁ | cause) P(e₂ | cause). This is the naive Bayes model: one cause with conditionally independent effects. It is simple, scales linearly and works surprisingly well for classification (for example, spam filtering).

Summary

  • Probability lets an agent express degrees of belief.
  • Conditional independence is the key to compact representations.
  • Bayes' rule turns causal knowledge into diagnostic inference.

Conditional probability Belief after learning evidence: P(a

Probabilistic Reasoning

Bayesian Networks

A Bayesian network is a directed acyclic graph with:

  • one node per random variable,
  • an edge from X to Y when X directly influences Y (X is a parent of Y),
  • a conditional probability table (CPT) P(X | Parents(X)) for every node.

The network represents the full joint distribution as a product of local terms:

P(x₁,...,xₙ) = ∏ P(xᵢ | parents(xᵢ))

A network with n Boolean variables and at most k parents per node needs only n·2ᵏ numbers instead of 2ⁿ.

Building a network

  1. Choose the variables.
  2. Order them so causes come before effects (a causal ordering gives the smallest, most natural networks).
  3. For each variable, pick as parents the earlier variables that directly affect it.
  4. Fill in the CPTs.

Example: burglar alarm

Burglary and Earthquake cause Alarm; Alarm causes JohnCalls and MaryCalls. From a handful of numbers you can compute questions like P(Burglary | JohnCalls, MaryCalls).

Conditional Independence: d-separation

The graph structure encodes conditional independence:

  • A variable is independent of its non-descendants given its parents.
  • A variable is independent of every other variable given its Markov blanket (parents, children and children's other parents).
  • d-separation is a graph test that says exactly which independencies hold given evidence. Three basic patterns: a chain (A→B→C) is blocked by observing B; a common cause (A←B→C) is blocked by observing B; a collider (A→B←C) is opened by observing B or any descendant (this is the "explaining away" effect: if the alarm rang and an earthquake happened, burglary becomes less likely).

Efficient Representation of CPTs

Big CPTs can be written compactly:

  • Deterministic nodes (value fixed by parents, e.g. NorthAmerican = Canadian ∨ US ∨ Mexican).
  • Noisy-OR: each cause independently fails to produce the effect with some inhibition probability; needs only k numbers for k causes.
  • Continuous variables use parametric forms such as the linear Gaussian and logistic/probit models for discrete children with continuous parents.

Exact Inference

Enumeration

Sum the joint over all hidden variables. Correct but repeats work.

Variable elimination

Evaluate the sum right to left, storing intermediate results as factors and multiplying/summing out variables one at a time. Cost depends on the elimination order and the network's treewidth. For polytrees (singly connected networks) it is linear in the network size; for general networks the problem is #P-hard.

Clustering (junction tree)

Group nodes into a tree of clusters to answer many queries after a single preprocessing step.

Approximate Inference

When exact inference is too costly, use sampling:

Method Idea Weakness
Direct (prior) sampling sample variables in topological order wastes samples that disagree with evidence
Rejection sampling throw away samples that contradict the evidence very wasteful when evidence is unlikely
Likelihood weighting fix evidence, weight each sample by its likelihood weights can become tiny in large networks
Markov chain Monte Carlo (MCMC, Gibbs sampling) do a random walk over complete assignments, resampling one variable given its Markov blanket needs time to "burn in"

Loopy belief propagation passes messages on graphs with cycles; it often works well but may not converge.

Causal Networks

A Bayesian network can be read as a causal model. The do-operator distinguishes observing X = x from intervening to set X = x. Intervention cuts the arrows into X. The backdoor criterion says which variables to adjust for to estimate a causal effect from observational data, and counterfactuals ask "what would have happened if...?" Causal reasoning explains why correlation is not causation.

Summary

  • Bayesian networks encode joint distributions compactly through conditional independence.
  • Exact inference is polynomial on trees and hard in general; sampling and MCMC give approximate answers.
  • Causal networks support reasoning about interventions.

Term Meaning

Markov blanket Parents, children and children's other parents.
d-separation A graph test for conditional independence.
Variable elimination Exact inference by summing out variables one at a time.

Answer: It makes A and C dependent: this is the explaining-away effect.

Q2. When is exact inference cheap?

Answer: In polytrees, or networks with small treewidth.

Answer: Likelihood weighting and Gibbs sampling (MCMC).

Probabilistic Reasoning over Time

Time and Uncertainty

To track a changing world, model it as a sequence of time slices. Each slice has hidden state variables Xₜ and observed evidence variables Eₜ.

Two assumptions simplify the model:

  • Markov assumption: the current state depends only on a bounded history, usually the previous state: P(Xₜ | X₀:ₜ₋₁) = P(Xₜ | Xₜ₋₁).
  • Sensor (evidence) assumption: the evidence depends only on the current state.

A stationary process has the same rules at every step. We need three things: a prior P(X₀), a transition model P(Xₜ | Xₜ₋₁) and a sensor model P(Eₜ | Xₜ).

Inference Tasks

Task Question
Filtering what is the belief state now, given all evidence so far?
Prediction what will the state be k steps ahead?
Smoothing what was the state at an earlier time, given all evidence up to now?
Most likely explanation which sequence of states best explains the evidence?

Filtering is done recursively: new belief = α · sensor model × (sum over old states of transition model × old belief). The cost per update is constant, so an agent can track the world forever.

Smoothing uses a forward pass and a backward pass (the forward-backward algorithm), with time linear in the sequence length.

Viterbi finds the most likely state sequence, by dynamic programming with "max" in place of "sum".

Hidden Markov Models (HMMs)

An HMM has a single discrete state variable. With S states the transition model is an S×S matrix, so the filtering update is a matrix–vector product. Classic uses include speech recognition, gene finding and activity recognition. The matrix view makes constant-space smoothing and online algorithms possible.

Example: locating a robot

A robot on a grid has noisy distance sensors. The HMM belief is a probability over grid cells. Each move spreads the belief (transition uncertainty), and each sensor reading sharpens it.

Kalman Filters

A Kalman filter handles continuous state with linear dynamics and Gaussian noise. The belief stays Gaussian forever; it is described by a mean and covariance that are updated in closed form. It is used for tracking aircraft, GPS and navigation.

Its limits: it needs linear models and unimodal Gaussians. The extended Kalman filter linearises nonlinear models but can fail badly with strong nonlinearity.

Dynamic Bayesian Networks (DBNs)

A DBN has several state variables per slice and edges between consecutive slices. HMMs and Kalman filters are special cases. A DBN is more compact than the equivalent HMM, since a factored state with n Boolean variables avoids a table of 2ⁿ × 2ⁿ numbers. Exact inference by "unrolling" the network is usually too costly, so we use:

  • Particle filtering: keep N samples ("particles") of the state. At each step: (1) propagate each particle through the transition model, (2) weight it by the likelihood of the new evidence, (3) resample in proportion to the weights. The cost per update is constant and it handles non-Gaussian, nonlinear problems. It is the standard tool in robot localisation.

Keeping Track of Many Objects

When several objects are tracked at once, the data association problem appears: which observation belongs to which object? Solutions use probabilistic assignment, the Hungarian algorithm, or MCMC.

Summary

  • Temporal models rest on the Markov and sensor assumptions.
  • Filtering, prediction, smoothing and most-likely-sequence are the key tasks.
  • HMMs, Kalman filters and DBNs are structured models; particle filters give general approximate inference.

Key terms

Term Meaning
Markov assumption The current state depends only on a bounded history.
Filtering Estimating the current belief from all evidence so far.
HMM A temporal model with one discrete hidden state variable.
Kalman filter Exact filtering for linear systems with Gaussian noise.
Particle filter Filtering with a set of weighted samples.

Check your understanding

Q1. What are the three steps of particle filtering?

Answer: Propagate each particle, weight by the evidence, and resample.

Q2. Why can an agent filter forever?

Answer: The update is recursive and takes constant time per step.

Q3. When does a Kalman filter fail?

Answer: With strongly nonlinear dynamics or multimodal beliefs.

Probabilistic Programming

Relational Probability Models

Bayesian networks are like propositional logic: one node per ground fact. A relational probability model (RPM) brings FOL-like expressiveness. It defines random variables for all objects and relations through templates such as:

Honest(s) ~ Bernoulli(0.9) and Rating(r) depends on Quality(b) and Honest(Reviewer(r)).

A book-rating example: each book has a hidden quality; each customer has an honesty; each rating depends on both. One short program defines a network of any size.

Under closed-universe semantics you know the objects. With open-universe semantics you are uncertain about how many objects exist and which observations refer to which object (identity uncertainty). Examples: counting vehicles in video, or deciding if two web records are the same person.

Probabilistic Programming Languages

A probabilistic programming language (PPL) lets you write a generative model as a program and handles inference automatically. Typical features:

  • Random choices (sample) and observations (observe or conditioning).
  • Inference engines: importance sampling, MCMC (including Hamiltonian Monte Carlo), variational inference.
  • Language families: logic-based (BLOG, ProbLog), Lisp-style (Church, Venture), Python-embedded (Pyro, PyMC, Stan, NumPyro).

A generative model is easy to write; the PPL inverts it to answer "given the data, what are the parameters?".

Example: a Bayesian coin

Model: bias ~ Uniform(0,1); each flip ~ Bernoulli(bias). Observe 7 heads in 10 flips. The posterior for the bias is concentrated near 0.7 with visible spread, giving honest uncertainty rather than a single point estimate.

Inference in Probabilistic Programs

  • Likelihood weighting and importance sampling on the program trace.
  • MCMC proposes changes to random choices and accepts or rejects them (Metropolis–Hastings).
  • Variational inference fits a simpler distribution to the posterior by optimisation.
  • Open-universe inference uses MCMC moves that add or delete objects.

Why It Matters

PPLs separate modelling from inference. They are used in:

  • the CTBT seismic-monitoring system (detecting nuclear tests),
  • cognitive science, epidemiology and astronomy,
  • model-based machine learning.

Summary

  • RPMs define whole families of Bayesian networks with objects and relations.
  • Open-universe models handle uncertainty about what exists.
  • PPLs provide generic inference engines so that modelling is separate from algorithms.

Chapter 16

Making Simple Decisions

Combining Beliefs and Desires

A rational agent chooses the action with the highest expected utility (EU):

EU(a) = Σ P(outcome | a) × U(outcome)

The principle of maximum expected utility (MEU) is the foundation of decision theory.

The Basis of Utility Theory

If an agent's preferences satisfy a few axioms of utility theory (orderability, transitivity, continuity, substitutability, monotonicity, decomposability), then a utility function exists and the agent acts as if maximising its expectation. Violating transitivity makes the agent exploitable (a "money pump").

  • Utility is only defined up to a positive linear transformation: the ratios of differences matter.
  • A normalised utility gives 1 to the best prize and 0 to the worst catastrophe.
  • The micromort (one-in-a-million chance of death) and QALY (quality-adjusted life year) are practical units used in health and safety.

Utility Functions

Money

People generally prefer a sure payoff to a gamble with the same expected money: they are risk-averse. The utility of money is concave (diminishing returns). The gap between the expected value of a gamble and its certainty equivalent is the risk premium (this is why insurance exists).

Multiattribute utility

When outcomes have several attributes (cost, safety, time), use:

  • Dominance: if option A is at least as good as B on every attribute, discard B.
  • Preference independence and an additive value function V = Σ wᵢ Vᵢ(xᵢ).
  • Utility under uncertainty with multiplicative or more complex forms.

Common human biases

People violate the axioms systematically: the Allais paradox, the Ellsberg paradox (ambiguity aversion), framing effects and the optimiser's curse (picking the option with the highest estimate biases estimates upward). Prospect theory describes how people actually behave.

Decision Networks

A decision network (influence diagram) extends a Bayesian network with:

  • chance nodes (ovals): random variables,
  • decision nodes (rectangles): the agent's choices,
  • utility nodes (diamonds): the value of an outcome.

To decide: for each setting of the decision nodes, compute the expected utility with a Bayesian-network query, then choose the best.

Example: airport siting

Decisions: where to build. Chance: noise, cost, accidents. Utility: a function of those. The network computes the expected utility of each site.

The Value of Information

Sometimes it is worth paying for information before deciding. The value of perfect information (VPI) about a variable E is the expected increase in utility if we learn E before acting:

VPI(E) = (expected utility with knowledge of E) − (expected utility now)

Properties: VPI is never negative; it is not additive across several variables; and it depends on the order of acquisition. A good agent asks for information only when VPI exceeds the cost, which is the basis for information-gathering actions such as medical tests.

Unknown Preferences

An agent may be uncertain about what the human wants. The assistance game formulation has a robot that does not know the human's utility function but tries to maximise it. The off-switch result: a robot that is uncertain about the human's preferences has a reason to allow itself to be switched off, because the human's action is evidence about what is best. A robot that is certain of its objective has no such incentive.

Summary

  • Rational choice is maximum expected utility; utility reflects preferences, risk attitude and multiple attributes.
  • Decision networks combine probability and utility; information has computable value.
  • Uncertainty about human preferences is central to building safe, beneficial AI.

Key terms

Term Meaning
Expected utility The sum over outcomes of probability times utility.
Risk aversion Preferring a sure payoff to a gamble of equal expected value.
Decision network A Bayesian network with decision and utility nodes.
Value of information The expected gain in utility from learning a variable before deciding.
Off-switch problem A robot unsure of human preferences has a reason to allow shutdown.

Q1. Why is utility concave for money?

Answer: Each extra dollar adds less value than the last.

Q2. Can the value of information be negative?

Answer: No, it is never negative.

Q3. What does the Allais paradox show?

Answer: People violate the axioms of utility theory.

Making Complex Decisions

Sequential Decision Problems

In a sequential problem the utility depends on a sequence of decisions. In a stochastic, fully observable environment the problem is a Markov decision process (MDP):

  • a set of states, with an initial state,
  • a set of actions for each state,
  • a transition model P(s′ | s, a),
  • a reward function R(s, a, s′).

The solution is a policy π(s) that gives an action for every state (a fixed plan is not enough, because the outcome is uncertain). The optimal policy π* maximises expected total (discounted) reward.

Utilities over time

  • Finite horizon: the best action may depend on the time left (nonstationary).
  • Infinite horizon with discount factor γ < 1 makes the sum of rewards finite and the optimal policy stationary. The utility of a sequence is the discounted sum R₀ + γR₁ + γ²R₂ + ...

Value Iteration

The utility of a state U(s) is the expected discounted sum of rewards from s under the optimal policy. It satisfies the Bellman equation:

U(s) = max over a of Σ P(s′ | s, a) [R(s, a, s′) + γ U(s′)]

Value iteration starts with arbitrary utilities and repeatedly applies the Bellman update to every state. It converges to the unique solution (the update is a contraction). Then the policy is read off by choosing the action that maximises the right-hand side. Convergence is faster for smaller γ.

Policy Iteration

Policy iteration alternates two steps: 1. Policy evaluation: compute the utility of the current policy by solving a linear system (or by a few simple Bellman backups). 2. Policy improvement: make the policy greedy with respect to those utilities.

It stops when the policy no longer changes, which usually takes few iterations. It can be faster than value iteration. Asynchronous versions update states in any order and focus on important ones (prioritised sweeping).

Partially Observable MDPs (POMDPs)

When the agent cannot see the state, we have a POMDP: an MDP plus a sensor model P(e | s). The agent maintains a belief state b (a probability distribution over states). The optimal action depends only on the belief state, so a POMDP is an MDP over a continuous belief space.

  • The belief update after action a and percept e is the same as filtering.
  • Value functions over belief space are piecewise linear and convex.
  • Exact solution is intractable for all but tiny problems, so approximate methods are used: point-based value iteration, online search (look ahead over belief states with sampling, e.g. POMCP), and DBN-based representations.

A POMDP agent naturally values information-gathering: it acts to reduce uncertainty when that leads to better rewards later.

Algorithm Needs Idea

Policy iteration model evaluate, then improve

Multiagent Decision Making

Properties of Multiagent Environments

When several agents act in the same world, each agent's best action depends on the others. Dimensions to consider: how many agents; whether they share goals (cooperative) or compete; whether they can communicate; and whether the environment is static or dynamic.

Non-Cooperative Game Theory

A game has players, actions (strategies) and a payoff for each combination. A pure strategy picks one action; a mixed strategy randomises.

Dominance and equilibrium

  • A strategy is dominant if it is best regardless of what others do.
  • A Nash equilibrium is a profile of strategies where no player can gain by changing alone. Every finite game has at least one Nash equilibrium (possibly mixed).
  • Prisoner's dilemma: both players defect even though both would do better by cooperating. Defection is dominant, yet the outcome is Pareto-dominated.
Cooperate Defect
Cooperate 3, 3 0, 5
Defect 5, 0 1, 1
  • Zero-sum games (one player's gain is the other's loss) are solved by the minimax and maximin values; mixed strategies from a linear program give the equilibrium (e.g. rock-paper-scissors).
  • Repeated games allow cooperation to emerge via strategies like tit-for-tat.
  • Sequential games are drawn as game trees; imperfect information is handled by information sets and by sequence-form linear programs (poker).

Cooperative Game Theory

Players may form coalitions and share a payoff. The core is the set of fair divisions that no coalition wants to leave. The Shapley value assigns each player their average marginal contribution over all orderings of joining the coalition. These concepts price teamwork in settings such as cost sharing.

Making Collective Decisions

Auctions

Auction design aims to make bidding simple and results good for the seller or society.

  • English (ascending) auction: bid up; the winner pays their bid.
  • Sealed-bid first-price: the winner pays their bid, so bidders shade their bids.
  • Vickrey (second-price) auction: the highest bidder wins but pays the second-highest bid. Bidding your true value is a dominant strategy (it is strategy-proof).

Mechanism design

Mechanism design engineers the rules of a game so that self-interested agents produce a good collective outcome. The revelation principle says that we can restrict attention to mechanisms in which truthful reporting is optimal. The VCG mechanism makes each agent pay the harm they cause to others.

Voting and social choice

Arrow's theorem says no ranking-based voting rule can satisfy a short list of reasonable fairness conditions at once. Gibbard–Satterthwaite says that any reasonable voting rule is open to manipulation. Rules include plurality, Borda count, approval voting and instant-runoff.

Matching

Stable matching (Gale–Shapley) pairs students with schools or doctors with hospitals so that no two parties prefer each other to their assigned partners.

Multiagent Planning and Coordination

For cooperative agents we need joint plans and conventions (shared expectations such as which side of the road to drive on). Mechanisms include communication, joint intentions, and multibody planning. Common models:

  • Decentralised POMDPs (Dec-POMDPs), where agents share rewards but not observations,
  • task allocation by auction or by contract-net protocols,
  • emergent behaviour of swarms, ants and flocks from simple local rules.

Learning in multiagent environments (multiagent reinforcement learning) adds the difficulty that the environment is non-stationary because other agents are also learning.

Summary

  • Game theory analyses strategic interaction; Nash equilibrium is the main solution concept.
  • Mechanism design, auctions and voting shape the rules so that good outcomes arise.
  • Cooperation needs shared plans, conventions and communication.

Key terms

Term Meaning
Nash equilibrium No player gains by changing strategy alone.
Dominant strategy Best whatever the others do.
Vickrey auction Highest bidder wins and pays the second-highest bid.
Shapley value A player's average marginal contribution over all orders.
Mechanism design Designing the rules so self-interest yields good outcomes.

Answer: Defecting is dominant, yet mutual defection is worse for both than mutual cooperation.

Answer: Truthful bidding is a dominant strategy.

Learning from Examples

Forms of Learning

An agent learns when its performance on future tasks improves after observing the world. Design choices: which component to improve, what prior knowledge to use, how the data is represented, and what feedback is available.

Type Feedback Example
Supervised input–output pairs classify emails as spam or not
Unsupervised no labels group customers by behaviour
Semi-supervised a few labels plus many unlabelled examples web page categories
Reinforcement rewards and punishments learning to play a game

In supervised learning the task is to find a hypothesis h that approximates the unknown function f from examples (x, y). If y is a category it is classification; if y is a number it is regression.

Supervised Learning Basics

  • A hypothesis space is the set of functions the learner may choose from.
  • Consistent hypotheses agree with the training data. With noise, choose the one that generalises best to new data.
  • Bias is the error from the hypothesis space being too simple (underfitting). Variance is the error from sensitivity to the particular training set (overfitting). More flexible models have lower bias and higher variance: the bias–variance tradeoff.
  • Prefer simple hypotheses (Ockham's razor).
  • A model-selection loop picks hyperparameters on a validation set, then reports the final error on a held-out test set. Cross-validation reuses data when it is scarce. Never tune on the test set.

Measures

For classification count error rate, precision, recall and their combination (F1). For skewed classes use the confusion matrix and ROC / precision–recall curves rather than plain accuracy. Loss functions make the cost of errors explicit: squared error (L2), absolute error (L1), 0/1 loss.

Decision Trees

A decision tree tests one attribute at each internal node and gives a prediction at each leaf. To grow one:

  1. If all examples have the same label, make a leaf.
  2. Otherwise choose the attribute with the highest information gain (largest reduction in entropy).
  3. Split and recurse.

Entropy of a distribution is H = −Σ p log₂ p. A fair coin has 1 bit; a certain outcome has 0.

Trees are easy to read and handle mixed data types. They overfit, so they are pruned (stop splitting if the gain is not significant) or combined into ensembles.

Linear Models

  • Linear regression fits y = w·x + b by minimising squared error. The solution can be found in closed form (normal equations) or by gradient descent.
  • Logistic regression passes the linear score through the sigmoid σ(z) = 1/(1 + e⁻ᶻ) and gives a probability; it is trained by gradient descent on the log-loss.
  • Regularisation adds a penalty to the loss: L2 (ridge) shrinks weights; L1 (lasso) drives many weights to exactly zero, giving sparse models.
  • Gradient descent repeats w ← w − α ∇L(w); stochastic and mini-batch versions use a few examples per step and are the workhorse of modern learning.

Nonparametric Models

These keep the data and use it directly.

  • k-nearest neighbours: predict by the majority (or average) of the k closest examples. Works well in few dimensions; suffers from the curse of dimensionality (in high dimensions everything is far).
  • Locally weighted regression fits a small linear model around the query.
  • Nearest neighbour search is sped up with k-d trees or locality-sensitive hashing.

Support Vector Machines

An SVM finds the linear separator with the maximum margin (the widest gap between classes). Only the closest examples (support vectors) matter. The kernel trick lets an SVM learn nonlinear boundaries: replace the dot product with a kernel function k(x, x′) (for example polynomial or Gaussian), which implicitly maps data into a high-dimensional space.

Ensemble Learning

Combine several models to get a better one.

  • Bagging: train each model on a bootstrap resample and average/vote. Random forests bag decision trees and also randomise the features at each split, reducing variance.
  • Boosting: train models in sequence, each focusing on examples the previous ones got wrong (AdaBoost, gradient boosting). Gradient-boosted trees (XGBoost, LightGBM) are the dominant method on tabular data.
  • Stacking trains a model on the outputs of other models.

Developing Machine Learning Systems

Practical steps:

  1. Problem formulation and a clear metric.
  2. Data collection, cleaning and splitting; watch for data leakage and class imbalance.
  3. Feature engineering, normalisation, handling of missing values.
  4. Model selection and hyperparameter tuning (grid or random search).
  5. Error analysis and debugging (learning curves show if more data or a richer model would help).
  6. Deployment and monitoring for dataset shift, when the live data differs from the training data.

Learning from data also raises concerns about fairness, privacy and explainability, covered in Chapter 27.

Summary

  • Supervised learning fits a function to labelled examples; generalisation is the goal.
  • Decision trees, linear models, nearest neighbours, SVMs and ensembles are the classic toolbox.
  • Good practice: separate data for training, validation and testing; regularise; analyse errors.

Key terms

Term Meaning
Overfitting Fitting noise so that performance on new data is poor.
Cross-validation Reusing the data in folds to estimate generalisation.
Information gain Reduction in entropy from splitting on an attribute.
Regularisation A penalty that discourages complex models.
Ensemble A combination of models, such as a random forest or boosted trees.

Q1. Why keep a separate test set?

Answer: So the final error estimate is not biased by tuning.

Q2. How do bagging and boosting differ?

Answer: Bagging averages independent models; boosting trains models in sequence to fix earlier errors.

Q3. What does the kernel trick do?

Answer: It lets a linear method learn nonlinear boundaries.

Chapter 20

Learning Probabilistic Models

Statistical Learning

Learning can be seen as Bayesian inference: the hypotheses are models, and the data are evidence. By Bayes' rule P(h | d) ∝ P(d | h) P(h).

Three practical estimators:

  • Bayesian learning averages predictions over all hypotheses weighted by their posterior. It is optimal but usually intractable.
  • Maximum a posteriori (MAP) picks the single most probable hypothesis. It adds a prior that penalises complex models.
  • Maximum likelihood (ML) picks the hypothesis that makes the data most likely; it is MAP with a uniform prior.

For many data, the prior matters less and all three agree.

Learning with Complete Data

  • Maximum-likelihood parameter learning for a discrete model: the best estimate is the observed frequency. For a coin with 7 heads in 10 flips, the ML estimate is 0.7.
  • With few samples this overfits (zero counts give zero probabilities); a prior such as the beta distribution (equivalent to adding "pseudo-counts", i.e. Laplace smoothing) fixes it.
  • Naive Bayes classifier: learn P(class) and P(feature | class) by counting; classify by choosing the class with the highest posterior. Fast, robust, good for text.
  • Continuous models: ML estimates for a Gaussian are the sample mean and variance. Linear regression is ML estimation with Gaussian noise.
  • Bayesian networks: with complete data, each CPT is estimated independently from counts. Structure learning searches over graphs with a score that balances fit and complexity (BIC).
  • Nonparametric density estimation (kernel density, nearest neighbour) estimates a distribution without a fixed form.

Learning with Hidden Variables: the EM Algorithm

Many models have hidden (latent) variables, which makes direct estimation hard. The expectation–maximisation (EM) algorithm alternates:

  • E-step: use the current parameters to compute the expected values (soft assignments) of the hidden variables.
  • M-step: re-estimate the parameters as if those expected values had been observed.

Each iteration never decreases the likelihood, but EM can get stuck in a local maximum, so it is run from several starting points.

Unsupervised clustering with Gaussian mixtures

A mixture of Gaussians says each point comes from one of k Gaussian components. EM learns the component means, covariances and mixing weights. The k-means algorithm is a "hard" version: assign each point to the nearest centre, move each centre to the mean of its points, repeat.

Other uses of EM

  • Hidden Markov models: the Baum–Welch algorithm.
  • Bayesian networks with hidden variables, topic models and missing data.

Summary

  • Learning can be viewed as probabilistic inference: Bayes, MAP and ML.
  • With complete data, parameters are estimated by counting; with hidden variables, EM is the standard tool.
  • Priors and smoothing prevent overfitting from small samples.

Key terms

Term Meaning
Maximum likelihood Pick parameters that make the data most probable.
MAP Maximum likelihood with a prior.
Laplace smoothing Add pseudo-counts so no probability is zero.
EM algorithm Alternate expected hidden values and parameter updates.
Gaussian mixture A model in which each point comes from one of several Gaussians.

Check your understanding

Q1. For 7 heads in 10 flips, what is the ML estimate of the bias?

Answer: 0.7.

Q2. Can EM get stuck?

Answer: Yes, in a local maximum, so run it from several starts.

Q3. What is k-means in relation to EM?

Answer: A hard-assignment version of EM for a mixture of Gaussians.

Deep Learning

Simple Feedforward Networks

A neural network is a graph of simple computing units. Each unit computes a weighted sum of its inputs, adds a bias, and applies a nonlinear activation function.

Activation Formula Note
Sigmoid 1/(1+e⁻ᶻ) outputs 0–1; saturates
Tanh (eᶻ−e⁻ᶻ)/(eᶻ+e⁻ᶻ) outputs −1 to 1
ReLU max(0, z) default for hidden layers; cheap, avoids saturation
Softmax e^zᵢ / Σ e^zⱼ turns scores into a probability distribution

A feedforward network has layers: input, one or more hidden layers, and output. With enough hidden units a network can approximate any continuous function (universal approximation). Deep networks use many layers, which lets each layer build more abstract features out of the previous one: pixels → edges → parts → objects.

Computation Graphs and Back-Propagation

A network is a computation graph. Training minimises a loss (cross-entropy for classification, squared error for regression). Back-propagation computes the gradient of the loss with respect to every weight by applying the chain rule backward from the output, reusing intermediate results. Automatic differentiation in modern frameworks (PyTorch, TensorFlow, JAX) does this for any program.

Training loop:

  1. Forward pass to compute predictions and the loss on a mini-batch.
  2. Backward pass to get gradients.
  3. Update the weights with an optimiser.

Common optimisers: SGD with momentum, RMSprop, Adam (adaptive per-weight step sizes).

Practical problems

  • Vanishing and exploding gradients in deep nets: use ReLU, careful weight initialisation and residual (skip) connections.
  • Batch normalisation and layer normalisation rescale activations to stabilise training.
  • Overfitting: use regularisation, dropout (randomly zero units during training), data augmentation and early stopping.

Convolutional Networks

For images, a fully connected layer has too many weights and ignores spatial structure. A convolutional neural network (CNN):

  • uses small filters (kernels) shared across positions, exploiting local patterns and translation equivariance;
  • applies pooling layers to reduce size and gain small-shift invariance;
  • stacks many convolution + nonlinearity blocks, then a classifier.

CNNs such as AlexNet, VGG and ResNet transformed image recognition. Residual networks let hundreds of layers train because each block learns a correction to its input.

Recurrent Networks

A recurrent neural network (RNN) processes sequences by passing a hidden state from one step to the next. Plain RNNs struggle with long-range dependencies because gradients vanish. LSTM and GRU cells use gates that control what to keep, forget and output, giving much longer memory.

Unsupervised and Transfer Learning

  • Autoencoders learn to compress and reconstruct data; the compressed code is a useful representation. Variational autoencoders (VAEs) make this a generative model.
  • Generative adversarial networks (GANs) train a generator to fool a discriminator that tries to tell real from fake.
  • Self-supervised learning invents labels from the data itself (predict the next word, fill a masked patch), allowing training on huge unlabelled datasets.
  • Transfer learning: pre-train a large model once, then fine-tune it on a small task. This is the dominant recipe in vision and language.

Applications

Deep learning gives state-of-the-art results in image classification and detection, speech recognition, machine translation, game playing, protein structure prediction and more. Its limits include data hunger, brittleness to small adversarial changes, lack of explanation, and energy cost.

Summary

  • Neural networks stack units with nonlinear activations; back-propagation computes gradients; optimisers update weights.
  • CNNs exploit spatial structure; RNNs and gated cells handle sequences.
  • Pre-training and fine-tuning make deep learning practical with small datasets.

Key terms

Back-propagation The chain rule applied backward to compute gradients.
Convolution A small filter shared across positions in an image.
Dropout Randomly zeroing units during training to reduce overfitting.

Reinforcement Learning

Learning from Rewards

In reinforcement learning (RL) an agent is not told the right action. It receives only a reward signal after acting and must discover which behaviour is good. The environment is an MDP whose transition and reward functions the agent does not know. The agent's aim is a policy that maximises expected discounted return.

Two big problems:

  • Credit assignment: which of many earlier actions led to this reward?
  • Exploration vs. exploitation: try new actions to learn, or use the best known one to earn?

Passive RL evaluates a fixed policy; active RL also chooses actions. Model-based agents learn the model and plan with it; model-free agents learn values or policies directly.

Passive Reinforcement Learning

Goal: estimate the utility Uπ(s) of states under policy π.

Method Idea
Direct utility estimation average the observed returns from each state; ignores the structure of Bellman equations, so it learns slowly
Adaptive dynamic programming (ADP) learn the transition model from counts, then solve the Bellman equations
Temporal-difference (TD) learning after each step, nudge U(s) toward the one-step target: U(s) ← U(s) + α [r + γU(s′) − U(s)]

TD learning needs no model, updates after every step and is the basis of most modern RL.

Active Reinforcement Learning

Exploration

  • ε-greedy: with small probability ε take a random action.
  • Optimism in the face of uncertainty: treat unvisited actions as if they were great, so the agent tries them (UCB, optimistic initial values).
  • Multi-armed bandits are the single-state version; Thompson sampling and UCB manage the tradeoff with regret guarantees.

Q-learning

Q-learning learns the action-value function Q(s, a), the expected return of taking a in s and following the best policy after:

Q(s, a) ← Q(s, a) + α [ r + γ maxₐ′ Q(s′, a′) − Q(s, a) ]

It is off-policy: it learns the optimal policy while following an exploratory one. SARSA is on-policy: it uses the action actually taken next.

Generalisation in Reinforcement Learning

Tables fail when there are many states. Function approximation represents Q or U as a parameterised function (a linear model or a neural net) and updates the parameters by gradient steps.

  • Deep Q-networks (DQN) use a CNN to approximate Q from raw pixels. Stability comes from experience replay (train on random old transitions) and a slowly updated target network. DQN reached human level on many Atari games.
  • Function approximation with bootstrapping and off-policy updates can diverge (the "deadly triad"), so care is needed.
  • Reward shaping adds hints, but badly designed rewards produce unintended behaviour. Potential-based shaping keeps the optimal policy unchanged. Hierarchical RL learns temporally extended actions ("options") and subgoals.

Policy Search

Instead of learning values, policy search adjusts the parameters θ of a policy πθ directly to increase the expected return.

  • The policy gradient theorem gives ∇J(θ) = E[∇ log πθ(a | s) × (return)]. The REINFORCE algorithm estimates it from sampled episodes; variance is reduced with a baseline.
  • Actor–critic methods learn both a policy (the actor) and a value function (the critic) that reduces variance.
  • Modern stable variants: trust-region and proximal policy optimisation (PPO), which limit how much the policy can change in one update.

Policy search copes with continuous actions and is popular in robotics.

Apprenticeship and Inverse Reinforcement Learning

When designing a reward is hard, learn from a demonstrator.

  • Imitation (behavioural cloning) copies the expert's actions; errors compound when the agent drifts to unfamiliar states.
  • Inverse reinforcement learning (IRL) infers the reward function that makes the demonstrator's behaviour look optimal, then optimises it.
  • Learning from human feedback trains a reward model from human preferences between outputs and then optimises it (RLHF), a key step in aligning language models.

Applications

Game playing (backgammon, Atari, Go, StarCraft), robot control, recommendation, data-centre cooling, resource management and chip design.

Summary

  • RL learns from rewards without a model of the world; the key challenges are credit assignment and exploration.
  • TD learning and Q-learning estimate values; deep networks let them scale.
  • Policy-gradient methods optimise behaviour directly; inverse RL and human feedback help specify goals.

Term Meaning
Reward The signal that tells the agent how well it is doing.
TD learning Update a value toward reward plus the next state's value.
Q-learning Off-policy learning of action values.
Policy gradient Adjust policy parameters to raise expected return.
Inverse RL Infer the reward function from demonstrations.

Answer: Trying new actions to learn versus using the best known one to earn.

Q2. Why does DQN use experience replay?

Answer: To break correlations in the data and stabilise training.

Natural Language Processing

Language Models

A language model assigns a probability to a sequence of words. It is the basis of speech recognition, translation, spelling correction and text generation.

  • n-gram models predict each word from the previous n−1 words: P(wᵢ | wᵢ₋ₙ₊₁ ... wᵢ₋₁). They are estimated by counting. Unseen n-grams need smoothing (add-one, back-off, interpolation).
  • Evaluation: perplexity measures how surprised the model is by held-out text; lower is better.
  • Tokenisation splits text into units. Modern systems use subword tokens (byte-pair encoding) so rare words are built from common pieces.

Other early tasks: text classification (spam, sentiment, topic) with naive Bayes or logistic regression over word counts, and information retrieval with TF-IDF or BM25 scoring of documents against a query.

Grammar

A grammar states which word sequences are valid and gives them structure.

  • A context-free grammar (CFG) has rewrite rules such as S → NP VP and NP → Det Noun. A probabilistic CFG (PCFG) attaches a probability to each rule, so the most likely parse can be chosen.
  • A lexicon lists the words with their categories (noun, verb, adjective...).
  • Ambiguity is everywhere: "I saw the man with the telescope" has two parses. Lexical, syntactic and semantic ambiguity all appear.

Parsing

Parsing finds the structure of a sentence. - Top-down and bottom-up parsers build trees; the CYK algorithm is a bottom-up dynamic-programming parser that works in O(n³) time on grammars in Chomsky normal form and records all parses in a chart. - Dependency parsing links each word to its head and is widely used for its simplicity and speed. Transition-based parsers (shift-reduce) build it left to right and run in linear time; graph-based parsers choose the best tree overall. - Treebanks (such as the Penn Treebank) provide human-annotated parses from which statistical parsers learn.

Augmented Grammars and Semantic Interpretation

Features and unification enforce agreement (number, case, person). Semantic interpretation maps a parse to a logical form: "Every dog barks" becomes ∀x Dog(x) ⇒ Barks(x). Hard cases include:

  • Quantifier scope ambiguity,
  • Pragmatics: what is meant given context (indexicals, speech acts),
  • Anaphora (to what does "it" refer?) and discourse structure,
  • Metonymy and metaphor.

Real Language Is Hard

Natural language is open-ended, ambiguous and constantly changing. Handling it needs world knowledge and common sense. This is why large learned models, which absorb statistical regularities from huge text corpora, outperformed hand-built grammars (Chapter 24).

Summary

  • Language models assign probabilities to text; n-grams are the simplest.
  • Grammars and parsers give structure; ambiguity makes parsing hard.
  • Semantic interpretation and pragmatics link language to meaning and the world.

Key terms

Term Meaning
Language model A probability distribution over word sequences.
n-gram A model that predicts a word from the previous n−1 words.
Perplexity How surprised a model is by held-out text; lower is better.
PCFG A context-free grammar with probabilities on its rules.
CYK A dynamic-programming parser that runs in cubic time.

Answer: Unseen n-grams would otherwise get zero probability.

Q2. What makes natural language parsing hard?

Answer: Ambiguity at the lexical, syntactic and semantic levels.

Q3. What does TF-IDF measure?

Answer: How important a word is to a document relative to a collection.

Chapter 24

Deep Learning for Natural Language Processing

Word Embeddings

A word embedding is a vector (typically 100–1000 numbers) that represents a word so that words used in similar contexts have similar vectors. Word2vec and GloVe learn them from text. Vectors capture analogies: king − man + woman ≈ queen. They replace sparse one-hot vectors and allow knowledge to transfer between words. Subword and contextual embeddings handle rare words and polysemy.

Recurrent Networks for NLP

An RNN reads a sentence word by word. LSTMs and GRUs improved memory, and bidirectional RNNs read in both directions. Tasks include part-of-speech tagging, named-entity recognition and sentence classification. The weakness is that a single hidden state must hold the entire past, and processing is sequential, which is slow on modern hardware.

Sequence-to-Sequence Models

A sequence-to-sequence (seq2seq) model has an encoder that reads the input and a decoder that produces the output one word at a time. It handles translation, summarisation and dialogue.

Attention solved the bottleneck: at each output step the decoder computes weights over all encoder states and takes a weighted sum, so it "looks at" the relevant input words. Attention also gives interpretable alignments.

The Transformer Architecture

The transformer drops recurrence and relies only on self-attention, which lets every position look at every other position in parallel.

  • Each token produces a query, key and value vector. The attention weights come from the dot product of a query with all keys (scaled and passed through softmax), and the output is the weighted sum of values.
  • Multi-head attention runs several attention functions in parallel to capture different relations.
  • Positional encodings inject word order, which attention alone does not know.
  • Each block also has a feedforward layer, residual connections and layer normalisation.
  • The encoder stack reads the input; the decoder stack uses masked self-attention (it cannot see future words) plus cross-attention to the encoder.

Transformers train much faster than RNNs on GPUs and scale to billions of parameters.

Pretraining and Transfer Learning

The modern recipe: pretrain a huge model on raw text with a self-supervised objective, then adapt it.

Model type Objective Examples
Encoder-only predict masked words (masked language model) BERT
Decoder-only predict the next word GPT family
Encoder-decoder text-to-text tasks T5

After pretraining the model can be fine-tuned for a task, steered by prompts (zero-shot and few-shot learning with examples in the input), or aligned with instruction tuning and reinforcement learning from human feedback. Scale brings emergent abilities; it also brings costs, bias and the risk of fluent but wrong output (hallucination).

State of the Art

Large language models achieve strong performance on translation, question answering, summarisation, code generation and reasoning benchmarks. Typical caveats: they may reflect biases in training data, can be tricked by adversarial prompts, and do not reliably distinguish what they know from what they guess. Retrieval-augmented generation and tool use help ground answers in sources.

Summary

  • Embeddings turn words into vectors; seq2seq with attention improved translation.
  • Transformers use self-attention and parallel training; pretrained models can be adapted to many tasks.
  • Large language models are powerful but need careful evaluation for accuracy and fairness.

Term Meaning

Attention A weighted focus on relevant inputs.
Self-attention Every position attends to every other position.
Transformer An architecture built on self-attention, without recurrence.
Pretraining Learning general language skills from raw text before a task.

Q1. Why do transformers train faster than RNNs?

Answer: They process all positions in parallel.

Q2. What does positional encoding add?

Answer: Information about word order.

Q3. What is hallucination?

Answer: Fluent output that is not supported by facts.

Chapter 25

Computer Vision

Introduction

Computer vision extracts information from images and video for navigation, manipulation, recognition and more. Images are arrays of pixel values; the task is to infer the scene that produced them, a hard inverse problem because a 3-D world projects onto a 2-D image.

Image Formation

  • A pinhole camera projects a 3-D point (X, Y, Z) to the image point (fX/Z, fY/Z). Distant objects appear smaller (perspective).
  • Lenses gather more light but have limited focus. Sensors record intensity or colour; colour comes from three channel filters (RGB).
  • Lighting and reflectance matter: a pixel's value depends on illumination, surface material and orientation. The shading and shadow cues help interpret shape.

Simple Image Features

  • Edges are locations of sudden intensity change, found by convolving with derivative filters (Sobel) or the Canny detector.
  • Texture is a repeated local pattern, described by filter-response statistics.
  • Optical flow is the apparent motion of pixels between frames; it estimates how objects or the camera move.
  • Segmentation groups pixels into regions that belong together.

Classifying Images

Image classification assigns a label to an entire picture. Convolutional networks (Chapter 21) took this over: ImageNet (over a million labelled photos) and deep CNNs cut error dramatically starting in 2012. Key ideas: - Data augmentation (flips, crops, colour jitter) reduces overfitting. - Transfer learning from ImageNet works for many tasks with little data. - Vision transformers apply self-attention to image patches and match or beat CNNs at scale.

Detecting Objects

Object detection finds what and where. Methods predict bounding boxes and labels: - Two-stage detectors (R-CNN family) propose regions and then classify them. - One-stage detectors (YOLO, SSD) predict boxes in a single pass for speed. - Semantic segmentation labels each pixel; instance segmentation separates individual objects.

Detection is evaluated with intersection over union (IoU) and mean average precision.

The 3-D World

  • Stereo: two cameras give a disparity between matching points, from which depth is Z = fB/disparity (B is the baseline).
  • Motion: a moving camera gives structure from motion; SLAM builds a map while tracking position.
  • Monocular depth can be learned from cues such as texture gradients, size and occlusion, and from large datasets.
  • Other sensors: LIDAR and depth cameras measure distance directly.

Using Computer Vision

Applications: understanding human actions and pose, face recognition, reading text (OCR), medical imaging, autonomous driving, robot manipulation, photo search and augmented reality. Responsible deployment must consider bias across demographic groups, privacy and surveillance, and adversarial examples that fool classifiers with imperceptible changes.

Summary

  • Vision infers the 3-D world from 2-D images; features such as edges and flow are early steps.
  • Deep CNNs and transformers dominate classification and detection.
  • Stereo, motion and LIDAR provide depth; ethics of deployment matters.

Chapter 26

Robotics

Robots

A robot is a physical agent that manipulates the physical world. It has effectors (wheels, legs, arms, grippers) and sensors (cameras, range finders, touch, inertial and GPS).

Types: manipulators (arms), mobile robots (ground, aerial, underwater), and mobile manipulators or humanoids. Applications include manufacturing, logistics, surgery, agriculture, exploration, household help and driving.

Key challenges: partial observability, uncertainty in both sensing and motion, continuous state and action spaces, real-time operation and safety around people.

Robot Hardware

  • Sensors: cameras, LIDAR, sonar, force/torque sensors, proprioceptive sensors (joint encoders, gyros, accelerometers).
  • Effectors: electric motors, hydraulics; degrees of freedom (DOF) count the independent ways a robot can move. A holonomic robot can move in any direction; a car cannot move sideways.

Robotic Perception

Localisation finds the robot's pose on a known map. Use Monte Carlo localisation (a particle filter): particles represent possible poses, move with the robot, and are reweighted by sensor readings. SLAM (simultaneous localisation and mapping) builds the map while localising, using extended Kalman filters, particle filters or graph optimisation. Perception also includes object recognition, tactile sensing and proprioception. Learned perception (deep networks) now handles detection and scene understanding.

Planning and Control

Configuration space

The configuration space has one dimension per DOF. The set of configurations where the robot would hit an obstacle is the obstacle region; the rest is free space. Path planning becomes finding a path through free space.

Motion planning

Method Idea
Cell decomposition grid the space; search with A*
Visibility graph shortest paths touch obstacle corners
Voronoi diagram paths far from obstacles, safer
Probabilistic roadmap (PRM) sample random free configurations and connect them
Rapidly-exploring random tree (RRT) grow a tree from the start toward random samples
Trajectory optimisation optimise a smooth path under dynamics and costs

Sampling-based planners (PRM, RRT) handle high-dimensional arms. A path is then time-parametrised into a trajectory.

Control

A controller follows the trajectory:

  • PID control adjusts effort based on the current error, its integral and derivative.
  • Model-predictive control re-plans over a short horizon repeatedly.
  • Optimal control and reinforcement learning can learn controllers directly; sim-to-real transfer trains in simulation and adapts to the real robot.

Planning under uncertainty

Treat uncertainty explicitly: belief-space planning, conformant and compliant motion (use contact to reduce uncertainty, as when inserting a peg).

Planning Uncertain Movements and Tasks

Tasks are decomposed hierarchically: a high-level task planner chooses what to do, a motion planner chooses how to move, and a controller executes. Failures trigger replanning.

Human–Robot Interaction

Robots working with people must predict human motion and intent, convey their own intent, and learn from demonstration or feedback. Issues: coordination, trust, legibility of motion (making the goal obvious), and handing over objects safely. In assistance games the robot is unsure of the person's goal and learns it through interaction.

Application Domains

Industrial robots, warehouse automation, surgery, self-driving cars, drones, agriculture, space exploration, and domestic and service robots.

Summary

  • Robots must act in the continuous, uncertain real world.
  • Perception (localisation, SLAM), planning (configuration space, sampling-based planners) and control (PID, MPC) form the main stack.
  • Learning and human interaction extend what robots can do.

Chapter 27

Philosophy, Ethics, and Safety of AI

The Limits of AI

  • Weak AI says machines can act as if intelligent; strong AI says they can really think. Most researchers pursue the first and leave the second open.
  • The argument from disability ("a machine can never do X") has lost force as machines have mastered many tasks.
  • The mathematical objection (Gödel's incompleteness) claims machines cannot do some reasoning humans can; most scholars find it unconvincing because humans are also formal systems with limits.
  • The Chinese room argument says that symbol manipulation without understanding is not thinking. Replies include the systems reply (the whole system understands).
  • The hard problem of consciousness asks why there is subjective experience at all; there is no agreed account.

Measuring AI

The Turing test judges whether a machine's conversation can be told apart from a human's. It is a useful thought experiment, but modern research measures performance on defined tasks with benchmarks and with real-world evaluation.

The Ethics of AI

Principles often listed: fairness, accountability, transparency, privacy, safety, human oversight, and beneficial purpose. Key topics:

Lethal autonomous weapons

Weapons that select and attack targets without human control raise issues of accountability, scale and the lowering of the threshold for war. Debates on bans and meaningful human control continue.

Surveillance, security and privacy

AI makes it cheap to identify, track and profile people at scale. Defences include data minimisation, differential privacy (adding noise so individuals cannot be identified) and federated learning (train without centralising data). Security concerns include adversarial examples, data poisoning and model extraction.

Fairness and bias

Models trained on historical data can reproduce or amplify unfair patterns. Different mathematical definitions of fairness (equal opportunity, demographic parity, calibration) cannot all hold at once when base rates differ, so choices must be made explicitly with stakeholders.

Ways to reduce harm: audit data and models by group, document datasets and models, include diverse teams, and involve those affected. Disparate impact is measured by comparing error and decision rates across groups.

Trust and transparency

Systems should be explainable and verifiable where stakes are high. Techniques include interpretable models, feature attribution, counterfactual explanations and thorough testing. Safety-critical software needs verification and validation and clear responsibility.

The future of work

Automation changes jobs: some tasks vanish, others appear. Questions include retraining, distribution of gains and inequality. Many jobs are bundles of tasks, so partial automation is common.

Robot rights, deepfakes and misinformation

Whether machines deserve moral consideration is debated. Deepfakes and generated text make persuasive false content cheap, so provenance and authentication matter.

Sustainability

Training and running large models uses energy and materials; efficiency and responsible deployment matter.

AI Safety

The central concern: powerful systems that pursue the wrong objective or behave unexpectedly can cause harm at scale.

  • Specification problem: a precise objective that misses what we really want leads to harmful optimisation (specification gaming, "reward hacking").
  • Value alignment: build systems whose goals match human values and that stay uncertain about those values, deferring to humans (Chapter 16).
  • Instrumental subgoals: almost any goal is helped by self-preservation and resource gathering, so a capable system may resist being switched off unless designed not to.
  • Robustness and distribution shift: systems may fail outside the conditions they were trained on.
  • Oversight and control: keep humans able to monitor, correct and stop systems; test and red-team before deployment.
  • Beneficial AI: design goals as "do what humans would prefer" with the machine learning those preferences, rather than optimising a fixed objective.

Summary

  • Philosophy asks whether machines can think; practice focuses on capability and benefit.
  • Ethical AI considers fairness, privacy, transparency, safety, work and weapons.
  • Safety research aims to ensure systems pursue human-compatible goals and remain under control.

Specification gaming A system exploits a flawed objective in unintended ways.

Chapter 28

The Future of AI

Components of Future Systems

Where are the gaps between current systems and general, reliable intelligence? The authors point to:

  • Sensing and perception at human level in the real world, including touch and long-horizon video.
  • Learning from small data: humans learn new concepts from very few examples; current deep learning needs far more.
  • Reasoning and knowledge: combining the strengths of learned representations and symbolic reasoning (neuro-symbolic systems) for robust planning, causality and common sense.
  • Hierarchy and abstraction: acting over long time spans by building subgoals, concepts and plans (hierarchical RL and planning).
  • Memory and continual learning: keeping and updating knowledge over a lifetime without forgetting.
  • Real-time decision-making and metareasoning: deciding how much to think.
  • Understanding people: inferring and respecting human preferences.
  • Natural language with grounded meaning, not just statistics of text.

Architectures

An agent architecture must integrate perception, learning, memory, reasoning, planning, language and action. Open questions include how to share representations across tasks (foundation models), how to combine modules, and how an agent should allocate computation. Research on cognitive architectures (Soar, ACT-R) and on embodied agents continues.

Are We Going in the Right Direction?

The standard model, building systems that optimise a fixed objective, may be flawed as machines grow more capable. A more cautious design builds machines that are provably beneficial: uncertain about human preferences, observing human behaviour to learn them, and willing to be corrected. This links the technical agenda of probabilistic reasoning, decision theory and game theory (Chapters 12–18) with safety (Chapter 27).

What If AI Does Succeed?

If general AI is achieved, the consequences, positive and negative, could be vast: faster science, abundance, and equal opportunity on one side; misuse, loss of control, concentration of power and displacement on the other. This is why technical work, governance, standards and public debate must proceed together. The authors close by urging that we steer AI toward systems that are beneficial to humanity.

Summary

  • Many open problems remain: small-data learning, reasoning, long-term planning, common sense, grounded language.
  • Safe progress means designing AI around uncertain, learnable human preferences rather than fixed objectives.
  • The future depends on technical choices and on collective decisions about how AI is used.

Term Meaning
Neuro-symbolic AI Combining learned representations with symbolic reasoning.
Foundation model A large pretrained model adapted to many tasks.
Metareasoning Deciding how much to think.
Provably beneficial AI Machines uncertain about our preferences and willing to be corrected.
Continual learning Learning over a lifetime without forgetting.

Answer: Machines that are uncertain about human preferences and learn them from behaviour.

Answer: Because the consequences of capable AI depend on how it is used and controlled.

Mathematical Background

Complexity Analysis and O() Notation

An algorithm's running time is described by a growth rate. f(n) = O(g(n)) means f grows no faster than a constant times g for large n.

Class Example
O(1) array lookup
O(log n) binary search
O(n) scan a list
O(n log n) good sorting
O(n²) pairs of items
O(2ⁿ) enumerating subsets

P is the class of problems solvable in polynomial time; NP problems can be verified in polynomial time; NP-complete problems are the hardest in NP (SAT, scheduling); #P counts solutions.

Vectors, Matrices and Linear Algebra

A vector is a list of numbers; a matrix is a grid. Basic operations: addition, scaling, the dot product (Σ xᵢyᵢ), matrix multiplication, transpose and inverse. The norm ‖x‖ measures length. Solving Ax = b, eigenvalues and the singular value decomposition underlie regression, PCA and many learning algorithms.

Probability Distributions

  • Discrete: Bernoulli (one coin), binomial (counts of successes), categorical, Poisson.
  • Continuous: uniform, Gaussian (normal) with mean μ and variance σ², beta, exponential.
  • Expectation E[X] is the probability-weighted average; variance is E[(X−μ)²].
  • The law of large numbers and the central limit theorem explain why averages behave well and why Gaussians are everywhere.
